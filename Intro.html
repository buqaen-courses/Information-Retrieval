Definition

What is Information Retrieval?

Given an information need, find — and rank — the relevant items in a large, unstructured collection.

🗄️ Database query

SELECT * FROM users WHERE age = 21

Structured data · exact match · results are correct or wrong

🔍 IR query

"best laptop for ML students"

Messy text · fuzzy intent · results are more or less relevant — a spectrum, not a boolean

SO WHAT

"Relevance" is graded and subjective — which is why ranking and evaluation exist at all.

The 2020s shift

LLMs didn't kill search.
They made it the bottleneck.

RAG — Retrieval-Augmented Generation

1 · Question "What's our refund policy for EU?"
2 · Retriever ← find the right 10 documents
3 · LLM reads only those 10 docs
4 · Answer grounded — or confidently wrong

An LLM without a good retriever is a brilliant writer with a terrible memory. The model can only be as good as the documents retrieval finds.

Every serious AI product in production right now — copilots, support bots, enterprise assistants — is secretly a search engine with a language model attached.

SO WHAT

Retrieval quality = answer quality. The people who build the retriever are the people this course trains.

Idea 01 · Indexing

The inverted index

The data structure behind every search box you've ever typed into.

TermPostings (documents)
search3, 7, 12, 18
vector7, 12
python3, 12, 41, 87, 102
embedding7, 41, 102

Instead of scanning every document for every query, pre-compute a map: term → documents containing it.

A query becomes dictionary lookups and list intersections — no scanning at all.

Same idea inside Lucene, OpenSearch, Elasticsearch — at petabyte scale.

SO WHAT

O(scan the whole corpus) becomes O(look up a word). You'll build one from scratch in Session 5.

Idea 02 · Retrieval models

Boolean retrieval — sets, not scores

Query: python AND search

Documents 3 and 12 contain both terms — intersect the postings lists.

AND = intersection · OR = union · NOT = set difference

Fast and precise — but binary. No way to say this document is more relevant than that one.

Still everywhere: e-commerce filters, legal discovery, log queries.

SO WHAT

Your first working engine — matching without ranking. Built in Session 6.

Idea 03 · Ranking begins

TF-IDF — documents become vectors

w(t,d) = tf(t,d) × loge ( N / df(t) )

Intuition: a word matters if it appears often in this document (tf) but rarely across the corpus (df).

"the" → weight ≈ 0. "embedding" → high weight.

Each document = a vector. Query too. Rank by cosine similarity — the angle between them.

SO WHAT

The first model that ranks, not just matches. Session 7 — computed with plain NumPy.

Idea 04 · The workhorse

BM25 — 30 years old, still hard to beat

score(D,Q) = Σq∈Q IDF(q) · f(q,D)·(k₁+1)f(q,D) + k₁·(1 − b + b·|D|/avgdl)

k₁ — saturation: the 10th occurrence of a word adds much less than the 1st.

b — length normalization: long documents shouldn't win just for being long.

Default ranking function in OpenSearch, Elasticsearch, Lucene — every day, everywhere.

SO WHAT

Every fancy neural ranker must beat this baseline. You'll implement it from the formula in Session 8.

Idea 05 · The scientific part

Without metrics, tuning is vibes

How do you know your ranking got better? You measure it against judgments (qrels).

P@k

Of the top 10 results — how many were actually relevant?

MRR

How high up did the first correct answer land?

MAP

Average precision across all relevant documents.

NDCG@10

The industry standard — rewards putting the best result first, with graded relevance.

You'll generate relevance judgments for a corpus, then treat every design change as an experiment with a score — like any serious ML system.

SO WHAT

You'll build metrics.py once in Session 10 — and reuse it all the way to the capstone.

Idea 06 · Meaning as geometry

Embeddings — search meaning, not spelling

A neural model maps text to a dense vector (~384 dims) where distance = meaning.

"buy laptop" lands near "notebook computers" — even though they share zero words.

Same math as TF-IDF cosine — but the vectors encode semantics, learned from data.

SO WHAT

Semantic search in pure NumPy, Session 12 — you'll see exactly where it beats BM25, and where it fails.

Idea 07 · ANN at scale

Vector databases & approximate search

Brute-force similarity = compare the query to every vector: O(N·d). At 10M docs, that's dead on arrival.

ANN indexes (HNSW, IVF, PQ) trade a tiny bit of recall for orders of magnitude in speed.

MilvusLanceDB≈99% recall in ~ms

Why not a B-tree? ANN isn't about ordered keys — it's about navigating a proximity graph.

SO WHAT

Hands on both Milvus and LanceDB in Session 13 — you'll compare them on the same data.

Idea 08 · Best of both

Hybrid search — fuse the two lanes

⚡ Lexical lane (BM25)

Exact SKUs, product codes, names, rare jargon

+

🧠 Semantic lane (kNN)

Paraphrases, intent, synonyms, typos

→

🔀 Reciprocal Rank Fusion

Merge two ranked lists into one — no score normalization headaches

Production systems almost never pick one lane. Query "A4 paper cheap" needs exact matching; "gift for a programmer girlfriend" needs meaning. Real engines run both.

SO WHAT

You'll build the full fusion pipeline in Session 22 — and measure hybrid vs. single-lane with your own metrics.

Idea 09 · Two-stage retrieval

Reranking — the biggest quality jump per line of code

10,000 docs · bi-encoder + ANN: fast, approximate — build the shortlist
100 candidates
10 results
🎯 Cross-encoder reranker

Reads query + document together — accurate but slow, so it only sees the shortlist of 100

Bi-encoder

Embeds query and doc separately. Pre-computable, millisecond-fast.

Cross-encoder

Attends across query + doc jointly. Far more accurate, far too slow for full corpora.

SO WHAT

Stage 1 for recall, stage 2 for precision — the standard architecture behind modern production search.

Idea 10 · Machine-learned ranking

Learning to Rank — let the data decide the order

FeaturesBM25 score · embedding similarity · price · freshness · popularity
→
ModelLightGBM / LambdaMART
trained on judgments or clicks
→
Ranked listoptimized directly for
NDCG — the metric itself
Pointwise → pairwise → listwise

Three ways to frame ranking as learning; each fixes the previous one's blind spot.

Where you've met it

Amazon, Booking, YouTube ordering — features + gradient boosting, tuned on behavior.

SO WHAT

Idea 11 · Acquisition & cleaning

Crawling the web — and knowing what you already have

🕷️ Polite crawling

robots.txt respected · rate limits · caching · pagination handling · incremental re-crawls

Being respectful isn't just ethics — banned IPs can't crawl at all.

👯 Near-duplicate detection

MinHash + LSH: find "these two descriptions are 95% identical" across millions of docs — without comparing every pair.

E-commerce lives and dies by this: same product, 40 sellers.

SO WHAT

Garbage in, garbage ranked. Sessions 17–20: you crawl a real product catalog and deduplicate it yourself.

Idea 12 · Systems engineering

Scale: you can't score everything — so cheat smartly

📦 Postings compression (delta + varint)🪜 Skip pointers✂️ Early termination🏁 WAND / block-max WAND

A query with 5 terms over 1M documents touches millions of postings. WAND-style pruning skips documents that cannot make the top-10 — identical results, a fraction of the compute.

This is where IR stops being "an ML problem" and becomes a systems problem: CPU caches, disk layout, memory buffers, index sharding.

SO WHAT

Session 11: benchmark your own index before and after optimization — and feel the difference.

Let's clear something up

Three myths CS students believe

"Search is a solved problem."

→ Reality: relevance is never "done." Every year the state of the art shifts — hybrid fusion and rerankers didn't exist as standard practice five years ago.

"Just throw a vector DB at it."

→ Reality: vector-only search silently fails on SKUs, names, codes, rare terms. Teams that shipped it are now rebuilding with hybrid pipelines.

"LLMs replaced search."

→ Reality: LLMs made retrieval the bottleneck (RAG). Someone has to build and tune the retriever. Be that someone.

SO WHAT

If any of these myths were true, this course would be history. Instead, its subject matter just became more valuable.
